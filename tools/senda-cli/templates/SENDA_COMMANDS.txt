SENDA CLI - GUIA RAPIDA DEL PROYECTO
======================================

Esta carpeta .senda/ conecta el proyecto con Senda. No guardes claves,
credenciales, codigo fuente, archivos .env ni datos de clientes aqui.

INSTALACION Y ACTUALIZACION
---------------------------
Instalar globalmente:
  npm install -g @prismadevs/senda-cli

Actualizar:
  npm update -g @prismadevs/senda-cli

Ayuda resumida:
  senda --help

TRABAJO PERSONAL DE DESARROLLADORES
-----------------------------------
1. Inicia sesión una vez en esta computadora:
  senda login

La CLI guarda la credencial personal en el almacén seguro del sistema, nunca
en el repositorio ni en .senda/. Para eliminarla: senda logout

2. Consulta y trabaja tus tareas:
  senda tasks pull
  senda tasks mine
  senda tasks available
  senda tasks claim <id>
  senda tasks claim 3
  senda tasks claim all
  senda tasks claim id-1,id-2,id-3
  senda tasks status <id> IN_PROGRESS
  senda tasks note <id> "Contexto, decision o bloqueo"
  senda tasks status <id> APPLIED
  senda tasks status <id> DONE

Estados posibles: IDEAS, IN_PROGRESS, APPLIED y DONE.

Cada vez que ejecutas `senda tasks pull` o `senda tasks mine`, la CLI actualiza
`.senda/.local/my-tasks.json`. Ese archivo no contiene tu token, esta ignorado
por Git y permite que un agente con acceso al repositorio vea tus tareas sin
necesitar credenciales. El campo `fetchedAt` indica cuando se consultaron.

Un reclamo siempre es atomico: si otro desarrollador toma una tarea antes,
Senda no la reasigna. En reclamos multiples se toman las que sigan libres y
se informa cuales no estuvieron disponibles.

SINCRONIZACION DEL PROYECTO
---------------------------
Despues de `senda login`, cualquier desarrollador asignado al proyecto puede
sincronizar los manifiestos autorizados. La sesion personal queda en el almacen
seguro del sistema, nunca dentro de .senda/ o Git.

Validar todo antes de sincronizar:
  senda validate

Solo comprobar la sincronizacion, sin enviar cambios:
  senda push all

Sincronizar con aprobacion explicita:
senda push knowledge --apply
senda push tasks --apply
senda push milestones --apply
senda push project-state --apply
senda push all --apply

Para CI o un agente no interactivo sin acceso al almacen seguro, se puede usar
SENDA_TOKEN como alternativa: es una clave restringida al proyecto y con
scopes definidos. Nunca debe guardarse dentro de .senda/ o Git.

QUE LEE SENDA AI
----------------
Senda AI solo lee archivos Markdown dentro de .senda/knowledge/. Escribe ahi
explicaciones funcionales confirmadas, aptas para clientes. Nunca copies codigo,
secretos, infraestructura privada, tokens, URLs privadas o datos personales.

ANTES DE ENVIAR CAMBIOS
-----------------------
1. Actualiza knowledge/, tasks.json, milestones.json o project-state.json con
   informacion verificada.
2. Ejecuta senda validate.
3. Revisa el diff con el responsable.
4. Solo entonces usa senda push ... --apply.
